# 贡献指南：把你的 Skill 交上来

贡献流程是**四步向导**。每一步都会告诉你"现在能做什么、下一步是什么"。

```
① 上传 SKILL.md  →  状态 draft
② 签贡献者协议    →  标记 cla_signed
③ 提交           →  状态 submitted
④ 评估并发布     →  状态 published      ──→  其他人的「Skill 库」里就能看到它
```

## 1. 两种创作者身份

| 身份 | `kind` | 适合谁 | 在站内怎么显示 |
| --- | --- | --- | --- |
| 个人创作者 | `personal` | 一个工程师自己的作品 | 贡献者列表里归到「个人」 |
| 部门 / 企业创作者 | `department` | 团队、部门、公司的对外产出 | 贡献者列表里归到「部门 / 企业」 |

身份只影响归类与署名，不影响流程与审核强度。
**不要用身份来"绕过"审核** —— 两种身份走的是同一条流程。

## 2. 第 1 步：上传

两种投递方式，任选：

- **上传文件**：把你的 `SKILL.md` 拖进去。
- **在线编辑**：直接在页面上粘贴正文（适合已经在别处写好的情况）。

可选再带一个 `bundle.zip`，里面是这个 Skill 需要的脚本与参考资料。

提交时还会填：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 贡献者名称 | ✔ | 你的名字或部门名，会成为 Skill 的作者 |
| Skill 名称 | ✔ | 会成为目录名，只允许小写字母、数字、连字符 |
| 版本号 | ✔ | 默认 `1.0.0`；同一 Skill 的同版本号不能重复发布 |
| 简介 | | 一句话说明"什么时候该用它" |
| 源码直链 | | 支持 **GitHub / Gitee / GitLab** 三种格式 |

**填写源码直链会发生两件好事**：

1. Skill 的身份变成 `<平台>:<owner>/<repo>/<name>`，别人能顺着地址找到原文；
2. 详情页会多出「源码直链」这一种分发方式。

不填的话身份是 `local:<贡献者>/<名称>`，也能正常用，只是追不到上游。

上传完成后系统会立刻做一次**预评估**（风险分 + 信号清单），
所以第 1 步结束时你就知道自己的 Skill 有没有"看着危险"的写法。

## 3. 第 2 步：签协议

填一个签名（你的名字即可）就完成。

> **为什么要签？** 这是一份"我确认这份内容我可以公开"的声明。
> 它记录的是**签名人与时间**，不做法律背书，但让协作有据可查。

签协议**不会**推进状态 —— "签了"和"提交了"是两件事。

## 4. 第 3 步：提交

点击「提交」。此时状态变 `submitted`，进入待发布队列。

没签协议就提交会被拦下，并明确告诉你："还没签贡献者协议，不能提交。"

## 5. 第 4 步：评估并发布

点击「评估并发布」，系统在一个事务里做六件事：

1. **重新扫描** SKILL.md 正文（+ bundle 里的文本文件），得到最终风险分
2. 算出 Skill 身份（`lib:` / `<平台>:owner/repo/name` / `local:贡献者/名称`）
3. Skill 不存在 → 新建；已存在 → 校验版本号唯一（**重复版本号直接 409 拒绝，绝不覆盖**）
4. 写一条版本快照（正文 + 大小 + 说明）
5. 写评估记录（`risk_audit` + 若干 `risk_signal`）
6. 登记贡献者档案，回填这条贡献记录

任何一步失败，整个发布回滚 —— 不会留下"半个 Skill"。

## 6. 写一份好 SKILL.md 的六条建议

1. **frontmatter 里必须有 `name` 和 `description`**。
   `description` 尤其关键：它就是 AI 判断"什么时候该用这份手册"的依据。
   写成"当用户要处理 PDF、拆分合并、填表单、做 OCR 时使用我"比写"PDF 工具"有用一百倍。
2. **写清边界**。允许做什么、**不允许**做什么，都写出来。含糊的权限描述本身就是风险信号。
3. **给出可复制的命令**，不要让读者猜。
4. **把大段参考资料放进 `references/`**，主文件保持短 —— AI 的上下文是有限的。
5. **不要包含密钥、内网地址、真实个人信息**。这三样是站内评估的重点红线。
6. **版本号要能讲清变化**：`1.0.0 → 1.0.1` 是修错字，`1.1.0` 是加能力，`2.0.0` 是不兼容改写。

## 7. 常见问题

**Q：发布后还能改吗？**
A：能。详情页有「编辑」，改完会自动追加一个版本快照，历史版本永远可回溯。

**Q：能删掉自己发布的东西吗？**
A：默认是**归档**（软删），列表里不再显示，但可以在「已归档」里找到并恢复。
物理删除需要管理员身份。

**Q：我的 Skill 被判定为「高风险」，是不是不能发布？**
A：可以发布，但风险分与等级会一直显示在详情页上。评估的作用是**让人知道风险**，
不是替人做决定。真要降分，按信号清单里的 `remediation` 逐条改。

**Q：重复提交同一个版本号会怎样？**
A：会被拒绝（HTTP 409），提示"版本 X 已存在"。换一个版本号即可 —— 这是为了不覆盖别人的历史。
