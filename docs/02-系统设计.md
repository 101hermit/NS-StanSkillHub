## 1. 新增的四个机制

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ② 动作层  MsAction（/api/v1/ms/**：schema/逻辑库/索引/约束/事件/台账/查询台）│
│           EvalAction（/api/v1/eval/**：实测/指标/汇总 · /agents · /mcp · 体检）│
└──────────────────────────────┬───────────────────────────────────────────┘
                               │
┌──────────────────────────────▼───────────────────────────────────────────┐
│ ③ 业务层  MsEngine          —— 写门禁：① 约束裁决 ② 索引维护 ③ 事件派发 ④ 台账 │
│           MsAdminService    —— 库/索引/约束/事件的 CRUD + 元数据总览 + 全库校验 │
│           MsQueryService    —— 受限 SQL：解析→白名单校验→固定模板执行→查询计划   │
│           EvalService       —— 单点实测 + 9 项指标 + 汇总 + TOPSIS            │
│           AccessService     —— Agent/MCP 注册、探活、出网自述、一键体检        │
└──────────────────────────────┬───────────────────────────────────────────┘
                               │ 只依赖 port
┌──────────────────────────────▼───────────────────────────────────────────┐
│ ④ 服务接口层  AgentPort（调用智能体）· McpPort（调用 MCP 工具）                │
│    适配器     AgentRouter → OpenAiCompatibleAgentAdapter / OfflineAgentAdapter│
│              McpRouter   → HttpMcpAdapter / BuiltinMcpAdapter                 │
│              NetEgress（代理 + 运行时从 PEM 构建 SSLContext）· CertLocator      │
└──────────────────────────────┬───────────────────────────────────────────┘
                               │
┌──────────────────────────────▼───────────────────────────────────────────┐
│ ⑤ 数据持久层  MsMapper（7 张 MS 表 + 事务台账）· EvalMapper（注册表/指标/实测） │
│              + 沿用简易版的 10 个 Mapper → 共 23 张表                        │
└──────────────────────────────────────────────────────────────────────────┘
```

**新增的外部依赖全部可离线**：`OfflineAgentAdapter`（确定性的本地桩）与
`BuiltinMcpAdapter`（进程内的 `skill_lookup` 工具）。断网时链路照样能跑通，
结果里显式标注 `offline=true` —— 功能链路与外部依赖彻底解耦。

## 2. 新增的 9 个类做了什么

| 类 | 行数量级 | 职责 | 关键设计 |
| --- | --- | --- | --- |
| `MsEngine` | ~450 | 写门禁全流程 | 约束判定是**纯函数**（`ConstraintEvaluator`），查库只通过 `Judge` 回调；事件日志同事务、动作在事务外 |
| `MsAdminService` | ~450 | 库对象 CRUD + 元数据 | 元数据总览带"术语小词典"，让不懂 DBMS 的人也能看懂 |
| `MsQueryService` | ~230 | 受限 SQL | 用户输入**永不进标识符位置**；值一律 `?` 绑定；逻辑表名映射到物理表名 |
| `EvalService` | ~480 | 实测 + 评分 | 指标口径 `SPECS` 是唯一真源（字典、打分、页面展示同源） |
| `AccessService` | ~260 | 注册 + 探活 | 探活口径：任何 HTTP 响应都算"通道可达"（证明网络与证书通了） |
| `NetEgress` | ~300 | 出网 | 运行时把 `config/certs/*.pem` 构建成 `SSLContext`，不需要用户手工 keytool |
| `ConstraintEvaluator` | ~250 | 7 类约束求值 | 纯函数 + `Judge` 接口，可脱离数据库单测 |
| `MsQueryParser` | ~330 | 受限 SQL 解析 | 精确错误定位（第几个词不认识）+ 可用列清单 |
| `Metrics` | ~230 | 评估指标与数理方法 | F1 / 覆盖 / 完整 / 完成 / 一致 + TOPSIS + z-score + 直方图，全纯函数 |

## 3. 关键时序

### 3.1 一次写操作（编辑 Skill）

```
PUT /api/v1/skills/{id}   （X-SKH-Role: editor）
  → SkillAction.edit
  → SkillService.edit（@Transactional）
      ① 身份校验
      ② MsEngine.beforeWrite("UPDATE", before, merged, actor)
           · 取该逻辑库下 ACTIVE 约束（含 default 公共约束）
           · 逐条求值：ENFORCED 违反 → 立即 422（含约束 code + 修复建议），并写 verdict=REJECT 台账
           · WARN 违反 → 收集告警，继续
      ③ skillMapper.updateSelective(改动字段)
      ④ 版本快照（版本号或正文变化时）
      ⑤ 正文变化 → 风险重扫 → risk_audit/risk_signal → 回填 risk_*
      ⑥ MsEngine.afterWrite(gate, "UPDATE")
           · 逐个 READY 索引：键值变化则追加条目、entry_count+1
           · 逐个 enabled 事件：触发匹配 + 条件成立 → 写 event_log(PENDING) → 执行动作 → DONE/FAILED/DEAD
           · 写 ms_tx_log（verdict=PASS/WARN + 约束命中 + 索引 + 事件）
      ⑦ op_log 审计
```

### 3.2 一次单点实测

```
POST /api/v1/eval/runs
  → EvalAction.run → EvalService.run（@Transactional）
      ① 校验输入与 Skill
      ② 组装系统提示：【Skill 名称】【Skill 说明】【行业场景】【Skill 手册(≤6000字)】【输出要求】
      ③ use_mcp → McpPort.call(...)，把工具返回拼进 user 输入
      ④ AgentPort.invoke(...) → Reply{output, reasoning, latency, ttft, tokens, offline, error}
      ⑤ score()：9 项指标（Metrics 纯函数）→ 加权总分 0-100
      ⑥ 落 eval_run（先写 score_total=0 再回写，因为该列 NOT NULL）+ eval_score
      ⑦ 回填 skill.eval_count / avg_score
```

### 3.3 查询台（安全边界）

```
POST /api/v1/ms/query  { sql: "SELECT name FROM skills WHERE risk_level='safe' LIMIT 5" }
  → MsQueryParser.parse(sql)
      · tokenize（保留单引号字符串、括号、比较符）
      · 校验：必须 SELECT 开头；表在白名单；列在白名单（否则 409/2100 并指出第几个词 + 可用列）
  → MsQueryService.run
      · 逻辑表名 → 物理表名（skills→skill, indexes→ms_index_def …）
      · 拼固定模板，值全部 ? 绑定
      · jdbc.queryForList 执行，返回 columns + rows + elapsed
POST /api/v1/ms/query/plan
      · 查 ms_index_def：WHERE 首列上有没有 READY 索引 → scan_type 与 used_index
      · 命中则 hit_count +1
```

## 4. 关键设计决策

| 决策 | 理由 | 代价 |
| --- | --- | --- |
| **写门禁放在业务层入口**而不是 AOP 或数据库触发器 | 可读、可断点、错误信息能带业务语义（哪个约束、怎么改） | 每个写方法要显式调一次；漏调就绕过（已用「所有写方法都过引擎」的评审清单兜住） |
| **事件日志同事务、动作在事务外** | 日志是事实必须与业务同生共死；动作有外部副作用不能回滚业务 | 动作失败要靠 `event_log` 重试与死信 |
| **约束求值做成纯函数 + Judge 回调** | 7 类约束可脱离数据库单测；查库只发生在需要的地方（UNIQUE / REFERENCE） | 组装 row 映射多一层 |
| **索引用真实条目表**而不是只存元数据 | 让"索引"可被查询、可被证明（页面上能看条目） | 每次重建要写 375 行；用 200/批缓解 |
| **查询台自己做解析器**而不是用 JSqlParser | 少一个依赖；能给出"第几个词不认识 + 可用列"这种精确提示 | 只支持单表子集 |
| **离线桩不是假成功** | 结果标 `offline=true` 并给出原因；分数照真实口径算 | 需要维护两套提示与输出形态 |
| **根证书运行时构建 SSLContext** | 内网用户不用会 keytool；换证书不用改启动参数 | 每次启动多 ~100ms 解析 PEM |
| **指标口径集中在 `EvalService.SPECS`** | 字典、打分、页面展示同源，避免"写的和算的不一致" | 新增指标要改一处代码 + 重灌字典 |

## 5. 性能预算

| 场景 | 目标 | 实测 |
| --- | --- | --- |
| 首次启动（23 张表 + 375 Skill + 种子） | ≤ 30 s | **~16 s** |
| 二次启动 | ≤ 8 s | ~5 s |
| 索引重建（375 行） | ≤ 1 s | ~0.4 s |
| 查询台（有索引） | ≤ 100 ms | 10–30 ms |
| 单点实测（离线桩） | ≤ 500 ms | 60–120 ms |
| 全库约束校验（375 × 5 条） | ≤ 3 s | ~1.2 s |
| 首屏 JS | ≤ 900 KB | **232 KB** |
